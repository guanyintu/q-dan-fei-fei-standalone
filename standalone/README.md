## 使用

1. 从 Releases 下载 `q弹狒狒.exe` 或完整 ZIP；启动 FF14，然后打开 `q弹狒狒.exe`。
2. 选择 `ffxiv_dx11.exe` 对应的进程，点击“连接游戏”。多开时在列表中选择正确 PID。
3. 勾选“Q 弹总开关”。默认强度 0.4、周期 0.45 秒，所有范围同步；可调整强度、周期、随机相位和角色范围。
4. 关闭开关恢复比例；“断开连接”会等待游戏主线程恢复模型并移除本模块的 Hook。关闭控制窗口时也走这一流程。

F6 开关、F7 强度档位、F8 重置视觉与音乐。快捷键默认禁用，可在窗口中开启；只在游戏前台且没有输入文字时生效，不吞掉游戏原按键。

本版本不提供游戏内 `/qbounce` 命令，使用独立控制窗口。若也安装了卫月版 q弹狒狒 或旧版 QBounce，请先关闭其效果，避免两个版本同时缩放相同模型。

## 版本与关键函数

参考客户端为国服 `2026.11.03.0000.0000`。

- 版本号不同：窗口显示未验证版本警告，继续进行关键校验。
- 关键签名不存在／匹配不唯一、帧入口异常、关键函数代码指纹不符或对象结构异常：停止启用，保留错误信息；失败状态的总开关不可开启。
- 检查包含游戏对象管理器、Framework、Conditions、GameMain、GPose 和输入入口；帧 Tick、GPose、常规角色和跟宠更新实现还对照参考客户端磁盘代码的长度与 FNV-64 指纹。

代码指纹是保守校验：编译后的相对调用偏移发生变化也可能要求更新适配。通过校验不能保证所有新版本、特殊模型或未覆盖代码路径都兼容。更新游戏后应先低强度检查普通场景。

## 本地模块与恢复

连接时由 EXE 使用 Windows API 加载它自己内嵌的模块；模块在游戏主线程更新已加载渲染根对象的三轴 Scale，不写角色服务器位置、速度、碰撞半径、游戏文件或网络协议。没有隐蔽加载、驱动、反作弊绕过或其他插件依赖。

模型身份包含槽位、地址、实体／模型 ID、DrawObject、Skeleton 和虚表。普通场景父节点允许处理；未加载、未知或附着到其他角色的模型跳过。过场、切图和 GPose 暂停；控制器退出或失去心跳时，下一游戏帧请求恢复并停止。

每帧先重新读取对象表槽位，再检查完整身份、父节点、加载状态和已缓存的函数入口。首次接纳对象时执行内存页、模型类型与入口检查；已接纳对象不再反复调用 VirtualQuery。异常访问由主线程回调的 SEH 保护触发自动停止。临时还原只标记变换更新，最终 Q 弹在角色最外层更新返回后通知一次；停用时仍立即更新恢复后的模型。

断开后移除 Hook、退出工作线程；为避免游戏回调与模块映像卸载的竞态，少量已停用模块映像保留至游戏退出，不再处理对象。异常残留变形时，关闭效果、断开，切图或重新登录；必要时重启游戏。不要强制终止游戏进程。

Windows N 等缺少系统媒体组件的环境可能无法播放音乐，此时 Q 弹继续。连接权限失败时显示 Windows 错误，不自动提权、不尝试绕过保护。

## 构建与验证

开发机需要 Visual Studio C++ Build Tools、Windows SDK 和 CMake；最终 EXE 不需要这些工具。仓库已包含 MinHook 1.3.4 源码。

```powershell
./standalone/build.ps1
```

输出在 `dist/q弹狒狒-独立版-0.2.2/`，同时生成程序 ZIP 与源码 ZIP。原生核心回归测试 25 项；另有直接调用生产代码的帧基准和 121 项回调／生命周期检查，覆盖倍率、恢复与不累积、NPC 加入／消失、地址复用、区域切换、嵌套更新、失效对象零写入、关键函数变化停止和插件启停。日志在 `dist/standalone-reports`。

性能基准：同机 Release 构建，100 个自有模拟对象、240 帧，直接执行生产模块的 Frame／ActorAfter。旧实现约 4.75 ms／帧、3494 次 VirtualQuery／帧、200 次变换通知／帧；优化后约 0.0054 ms／帧、0 次 VirtualQuery／帧、100 次通知／帧。模拟变换函数只计数，不计算游戏骨骼，因此这些数值只反映控制逻辑开销，不能换算为游戏 FPS 或保证实机耗时。大量新对象接纳时仍需要完整校验；随机相位需要逐对象计算。

`inspect_client.py` 只用于开发者人工核查参考客户端；不要在游戏更新后直接重生成指纹以绕过失败。`read-status.ps1 -GameProcessId <PID> -RequireRunning` 读取程序自己的本地控制通道，用于验证真实回调运行。

已确认导入项仅为 Windows 系统 DLL。用户已确认 0.1.1 可以正常启用；0.2.2 的实机帧率、装备武器传播、所有种族／特殊 BOSS 和长时间稳定性仍需验收，不能用编译或单元测试替代。比较卡顿时使用同一场景和视角，关闭卫月版效果，分别切换独立版总开关观察帧率；也可关闭 BGM 排查音频输出的影响。
